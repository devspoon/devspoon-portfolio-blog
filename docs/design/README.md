# 디자인 시안 — STOP ① 비교 자료 (2026-11-12)

보는 법: `docs/design/sketches/*.html`을 브라우저로 열고 오른쪽 위 달 아이콘으로 라이트/다크 전환. 촬영본은 `sketches/shots/`
(`{a|b}-{light|dark}-{1366|390}.png`). 두 시안은 **같은 `components.css`(base·components 층)** 를 쓰고 토큰·히어로만 다르다
— 계획의 "토큰만 바꾸면 전체 디자인이 바뀐다" 구조를 그대로 검증한 것.

## 공통 (어느 쪽을 골라도 동일)
- Pretendard Variable, 글자 7단계 유동 크기, 4px 간격, 반경 3단계, 그림자 최소, 포커스 링, 다크 모드, 모션 감소 대응
- 카드 4변형(글 행·프로젝트·주제·폼 표면)이 `.c-card` 하나에서 파생
- Bootstrap은 `@import … layer(vendor)`로 **vendor 층에 넣어야 한다**(층 밖 CSS가 모든 층 규칙을 이기는 문제를 시안 1차에서 확인 — ADR-015)

## 비교
| 항목 | A 엔지니어링 노트 | B 청사진 |
|---|---|---|
| 인상 | 조용한 기술 노트, 읽기 중심 | 백엔드 엔지니어 정체성이 강하게 드러남 |
| 기억에 남는 요소 | 거대한 이름 타이포 + 실제 데이터 "최근 작업" 로그 | 기술 스택 연결도(노드별 글 수, 링크) |
| 강조색 | 기존 브랜드 코랄 계승(글자용 #C23A44로 대비 보정) | 앰버(브랜드 변경) |
| 다크 모드 | 남색 기운 어두운 면, 자연스러움 | 히어로·본문 모두 남색 계열로 통일감 큼 |
| 모바일 | 그대로 잘 쌓임 | **다이어그램 글자가 작아 읽기 어려움 → 모바일은 목록형 대체 필요** |
| 구현 비용 | 낮음(히어로는 템플릿 데이터만) | 중간(다이어그램 데이터: 태그·기술별 글 수 집계 필요) |
| impeccable 감지 | 0건 | 히어로 여백 1건(계산식 오탐 추정) + 권고 1건(모눈 배경은 생성형 UI 흔한 특징 — 단 도면 표현은 예외로 명시) |
| frontend-design 기본값 점검 | 크림·테라코타/검정·형광/신문형/동일 카드 반복/대문자 라벨/`·` 메타/`→` 버튼 없음 | 동일. 모눈 배경은 주제(도면)에 근거한 선택 |

## 자기 비평 기록
- 1차 시안에서 히어로 로그·푸터에 `·` 메타 연결 사용 → 지침상 흔한 기본값이라 별도 요소로 분리
- 무작위 사진 썸네일 → 실제 프로젝트를 오해하게 하므로 이름이 든 중립 자리표시로 교체(실구현은 실제 스크린샷/대표 이미지)
- B 히어로 배경 단축 속성 오류(색 위치) 수정, 로고 강조 글자 대비 부족 수정(글자용 강조색 토큰 사용)

## 권장
**A를 기반으로, 포트폴리오 페이지에만 B의 스택 연결도를 "기술 스택" 섹션으로 차용**하는 조합을 권장한다.
홈은 글·작업 기록이 주인공인 A가 블로그 독자에게 맞고, 스택 연결도는 채용 담당자가 보는 포트폴리오에서 정체성을 가장 잘 보여 준다.
