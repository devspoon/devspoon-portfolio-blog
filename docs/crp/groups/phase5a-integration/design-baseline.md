> 이 그룹의 요구사항·설계 결정의 단일 기준. append-only.

## 0. 질의 수준 (Autonomy Level)

- [x] **적극(Thorough)** · 선택일: 2026-11-13

> 사용자 규칙: 설계·작업 계획 승인 후 실행. 실행 중 계획 밖 수정이 필요하면 고치기 전에 멈추고 묻는다. 커밋만 하고 push·병합(main)·배포는 하지 않는다.

## 1. 목적 / 배경

이 세션의 백엔드 작업(브랜치 `crp/phase4-data-integrity`, 1~4단계)과 다른 세션의 템플릿 작업(브랜치 `template-phase3-redesign`, 그쪽 1~3단계: 보안·구조·디자인 개편)이 main(`5b647a4`)에서 갈라져 같은 파일을 고쳤다. 5단계(요청 처리 보안)의 GET→POST는 그쪽 1단계에서 이미 했다. 같은 일을 다시 하지 않도록 먼저 통합한다.

- 그쪽 브랜치는 **`287639c`로 고정**해 합친다. 그쪽 세션이 이후 커밋을 더 쌓으면 다시 합쳐야 한다(R-001).
- 그쪽 worktree·브랜치는 읽기만 한다. 통합 결과는 새 브랜치 `crp/phase5a-integration`(이 worktree)에만 만든다.
- 병합 전 계산(`git merge-tree`): 내용 충돌 18개 파일 + git이 잡지 못하는 이름 충돌 1개(그쪽 `common/mixin/views.py` 모듈 ↔ 이쪽 `common/mixin/views/` 패키지).

## 4. 불가침 제약

- C-1: 양쪽 테스트 전부 통과(이쪽 402 + 그쪽 테스트). 지우거나 skip해서 통과시키지 않는다.
- C-2: 그쪽 worktree·브랜치는 수정하지 않는다. main에 병합하지 않는다. push하지 않는다.
- C-3: 스키마 변경은 이쪽 4단계 좋아요 제약과 그쪽에 있던 것만. `makemigrations --check`로 확인.
- C-4: WSL의 다른 컨테이너와 로컬 DB 백업은 건드리지 않는다.
