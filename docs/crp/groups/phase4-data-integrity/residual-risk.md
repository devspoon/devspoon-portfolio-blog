# Residual Risk — phase4-data-integrity (잔여 위험 등록부)

| ID | 항목 | Severity | 왜 비범위인가 | 수용일 | 재평가 조건 |
|---|---|---|---|---|---|
| R-001 | 운영 DB 반영은 사용자가 deploy.md 순서대로 실행해야 한다. 정리 명령 전에 `migrate`를 하면 중복이 있을 때 migration이 실패한다(데이터는 바뀌지 않음) | MED | 배포·운영 실행은 사용자 몫(phase1 REQ-002). migration을 서버에서 만든다 | 2026-11-13 | 배포 요청 시 deploy.md를 함께 확인 |
| R-002 | 좋아요 연결 모델의 FK가 nullable이라 NULL 행은 제약으로 막히지 않는다 | LOW | 정상 경로에서는 NULL이 생기지 않는다(CASCADE). nullable 변경은 스키마 변경 확대 | 2026-11-13 | NULL 행이 발견되면 정리 대상에 넣을지 결정 |
| R-003 | 좋아요 토글은 아직 GET 요청이다(CSRF 없이 다른 사이트가 유도 가능) | MED | 5단계(요청 처리 보안) 범위 | 2026-11-13 | 5단계 착수 시 |
| R-004 | `table_name` 컬럼은 남아 있지만 검색은 더 이상 읽지 않는다 | LOW | 컬럼 삭제는 스키마 변경 확대. 저장 값은 `save()`가 맞춘다 | 2026-11-13 | 다음 스키마 정리 때 삭제 여부 결정 |
| R-005 | 좋아요 토글의 replica 읽기 문제는 잠금 안의 두 읽기만 default로 고쳤다. 다른 뷰의 "쓰기 직후 replica 읽기"(예: 댓글 작성 뒤 글 조회)는 실제 replica가 지연되면 옛 값을 볼 수 있다 | MED | 5단계(요청 처리 보안의 replica 읽기 지연) 범위 | 2026-11-13 | 5단계 착수 시 |
| R-006 | `PostMixin.__table_name__`은 인스턴스에 없는 `self.__name__`을 읽어 호출하면 오류다. 호출하는 곳은 없다 | LOW | 쓰이지 않는 코드, 범위 밖 | 2026-11-13 | 6단계 소규모 정리에서 삭제 검토 |
