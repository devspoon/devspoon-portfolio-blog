# Design Baseline — phase6-small-cleanups

> 상위: 원래 검토의 "소규모 정리" 단계. 브랜치 `crp/phase6-small-cleanups`(5단계 `fe00ffe` 위).

## 0. 질의 수준
보통 — 사용자에게 보이는 정책만 묻는다.

## 1. 범위
원래 항목 M4·N2·M8·N3·R2·R3, 5단계 R-005(닉네임), 쓰지 않는 `__table_name__`. 조사 중 N2의 형제 버그(수정 폼 태그 합쳐짐) 추가.

## 3. 설계 결정 기록 (ADR)
| ADR-ID | 결정 | 근거 | 상태 |
|---|---|---|---|
| ADR-001 | (N2+) 수정 폼 4개의 태그 초기값을 `",".join`으로(opensource 폼과 같게). `tag_save`는 쉼표로 나눈 뒤 앞뒤 공백 제거·빈 값 제외·중복 제거. 140자(DB 상한) 넘는 태그는 폼 오류로 다시 입력받는다(D2). 죽은 정규식 줄 삭제 | 지금은 태그 있는 글을 수정 화면에서 저장만 해도 태그가 하나로 합쳐진다. `"a, b"`는 `" b"` 태그를 따로 만든다. 140자 넘으면 PostgreSQL `DataError` 500 | Accepted |
| ADR-002 | (M4) 태그 검색은 키워드 검색처럼 현재 페이지(`page_obj.object_list`)만 넘기고, `tag`는 검색어 문자열로 넘긴다 | 지금은 모든 페이지에 전체 결과가 나오고, 제목에 QuerySet 표현이 찍힐 수 있다 | Accepted |
| ADR-003 | (M8) 파일 교체 시 옛 파일 정리 반복문에서 빈 필드를 만나면 `return` 대신 `continue`. 블로그·사용자 두 곳 | 블로그 글은 `file1`이 비어 있으면 `file2`를 바꿔도 옛 파일이 남는다 | Accepted |
| ADR-004 | (R3) OS 통계의 mac 판정을 `"Macintosh"` 포함 여부로 | `"mac"`(소문자)은 실제 UA(`Macintosh; Intel Mac OS X`)와 안 맞아 mac은 늘 0. iPhone UA는 `Macintosh`가 없어 섞이지 않는다 | Accepted |
| ADR-005 | (R2, D1) 이메일 도메인 검사: 도메인을 점으로 나눈 이름 중 하나가 정확히 `test`일 때만 거부. 가입·문의 폼 두 곳 | 지금은 `contest.com`, `latest.io` 같은 정상 주소도 막는다 | Accepted |
| ADR-006 | (5단계 R-005) 프로필 닉네임은 `UserProfile.nickname` 기준으로 겹치지 않을 때까지 `base`, `base1`, `base2`…로 정한다. 가입 닉네임·이메일 앞부분 둘 다 | 지금은 닉네임을 사용자 이름 목록과 비교해 겹침을 못 막고, 겹치면 `IntegrityError` 500 | Accepted |
| ADR-007 | (N3) 관계 필드를 보여 주는 admin 목록(블로그·게시판 글과 댓글, 사용자 프로필·인증, 포트폴리오 프로젝트)에 "행 1개와 5개의 쿼리 수가 같다" 테스트를 둔다. 늘어나는 곳만 `list_select_related` 등으로 고친다 | dev DB 측정(블로그 글 38행 7쿼리, 댓글 24행 5쿼리, 문의 19행 4쿼리)에서는 N+1이 없었다. 빈 테이블은 측정 못 했다 | Accepted |
| ADR-008 | 쓰지 않는 `PostMixin.__table_name__` 삭제(호출처 0, 호출하면 `AttributeError`) | 죽은 코드 | Accepted |

## 4. 불가침 제약
- C-1: 기존 테스트 전부 통과(692 + 새 테스트).
- C-2: 스키마 변경 없음. 이미 쌓인 통계·태그 데이터는 고치지 않는다(D3).
- C-3: push 안 함. 그쪽 worktree·브랜치, 다른 WSL 컨테이너, 로컬 DB 백업 건드리지 않음. 운영 DB 명령 없음.
