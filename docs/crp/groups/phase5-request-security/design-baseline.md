# Design Baseline — phase5-request-security

> 상위: 원래 검토의 "요청 처리 보안" 단계. 브랜치 `crp/phase5-request-security`(통합 `346c979` 위).

## 0. 질의 수준
보통 — 사용자에게 보이는 동작·정책만 묻고 구현 세부는 자동 결정.

## 1. 범위 정리 — 원래 항목 중 남은 것
| 원래 항목 | 상태 |
|---|---|
| 삭제·좋아요 GET→POST, JS 수정 | 그쪽 세션 template-phase1에서 완료, 통합에 포함 |
| 좋아요 race | 이쪽 phase4 ADR-003에서 완료 |
| **replica 읽기 지연** | **이번 범위**(phase4 R-005) |
| **댓글 생성 검증(M5)** | **이번 범위** |

## 3. 설계 결정 기록 (ADR)
| ADR-ID | 날짜 | 결정 | 근거 | 상태 |
|---|---|---|---|---|
| ADR-001 | 2026-11-13 | (D1-A 승인) 라우터에 "primary 고정" 컨텍스트를 둔다. ① POST 등 상태 변경 요청은 요청 전체의 읽기를 `default`에서 한다(미들웨어). ② 캐시를 새로 채우는 빌더(`cached()`·댓글 목록)는 `default`에서 읽는다. | 캐시 TTL이 24시간이라 무효화 직후 늦은 replica에서 다시 채우면 옛 값이 하루 동안 남는다. 쓰기 트랜잭션 안의 읽기를 replica로 보내면 커밋 전 값을 못 본다(댓글 `group` 계산). 뷰마다 `.using("default")`를 붙이는 대신 한 곳에서 막는다. | Accepted |
| ADR-002 | 2026-11-13 | 댓글 생성·수정 뷰 16개(복사본 8쌍)를 `common/mixin/views/`의 `ReplyCreateMixin`·`ReplyUpdateMixin`으로 모은다. 각 뷰는 `reply_model`·`detail_url_name`만 정한다(phase3 `ReplyListJsonMixin`과 같은 방식). | 검증을 8번 복사하지 않는다. 복사본은 FK 이름(`post`/`board`)만 다르다. | Accepted |
| ADR-003 | 2026-11-13 | 댓글 생성 검증: 글은 활성 글만(삭제·숨김 → 404, phase3 D1-A와 같음), 부모는 같은 글의 댓글만(없음·숫자 아님·다른 글 → 400), `depth`는 서버가 `min(부모 depth + 1, 3)`으로 계산(클라이언트 값 무시, JS `MAX_DEPTH`와 같음), 공백뿐인 댓글은 지금처럼 저장 없이 돌아감. 글 행 잠금·`group` 증가·댓글 생성·`reply_count` 증가를 한 트랜잭션으로. | 지금은 없는 부모 → `DoesNotExist` 500, 다른 글 댓글에 대댓글 가능, `depth` 조작 가능, 삭제·숨김 글에 댓글 가능. | Accepted |
| ADR-004 | 2026-11-13 | 댓글 수정 검증: JSON이 아니거나 `comment`가 문자열이 아니면 400, 그 글의 댓글이 아니면 404, 공백뿐이면 400. `comment`가 `null`이면 지금처럼 변경 없이 응답. | 지금은 잘못된 JSON·키 누락이 500이고, 빈 댓글로 바꿀 수 있다. | Accepted |
| ADR-005 | 2026-11-13 | (D2-A 승인) 댓글은 3000자까지. 생성·수정 모두 서버가 검증(넘으면 생성은 저장 없이 400, 수정은 400), 입력창 `maxlength="3000"`. | 상한이 없으면 요청 한도(2.5MB)까지 저장되고 댓글 목록 캐시에 그대로 들어간다. | Accepted |
| ADR-006 | 2026-11-14 | (F-005, 권장안 A) `users.models.on_save_user`의 본문을 `read_primary()` 안에서 실행한다. 로직은 그대로 `_ensure_profile()`로 옮긴다. | GET으로 끝나는 로그인 흐름(소셜 콜백 등)은 미들웨어가 primary로 돌리지 않는다. 시그널 하나만 고치면 모든 경로가 막힌다. | Accepted |

## 4. 불가침 제약
- C-1: 기존 테스트 전부 통과(548 + 새 테스트). 지우거나 skip해서 통과시키지 않는다.
- C-2: 댓글 화면 계약 유지: 생성은 폼 POST 후 상세로 redirect, 수정은 JSON `{"message"}`, 목록 JSON 모양(통합 ADR-007).
- C-3: 스키마 변경 없음(`makemigrations --check`).
- C-4: push 안 함. 그쪽 worktree·브랜치, 다른 WSL 컨테이너, 로컬 DB 백업 건드리지 않음. 운영 DB 명령 없음. 인프라 배포 yml 변경 없음.
